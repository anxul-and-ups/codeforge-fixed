# CODE FORGE v2 — Comprehensive Codebase Audit (`AUDIT.md`)

## 1. Architecture Found in v1

- **Tech Stack**: Kotlin, Jetpack Compose (Material 3), Room Database (`AppDatabase` v1), OkHttp, Android Keystore (`KeyStoreManager`), SharedPreferences (`SettingsStore`), Coroutines & StateFlow.
- **Execution Model**: Currently, all file operations (`ProjectRepository`) operate strictly inside `context.filesDir/projects/<uuid>`. There is **zero Termux integration** (`RUN_COMMAND` permission is missing, no localhost bridge, no shell execution, no package or tool installation).
- **Agent Loop (`AgentEngine.kt`)**: Runs in-process on `CodeForgeApp.agentScope`. Supports basic tools (`list_files`, `read_file`, `search_code`, `edit_file`, `write_file`, `delete_file`, `move_file`, `finish`), plus GitHub REST API push & Actions build polling (`GitHubManager`).
- **Provider & Failover Layer (`ProviderRepository.kt` & `LlmClients.kt`)**: Supports Anthropic, OpenAI-compatible, and Gemini streaming. However, it initializes hardcoded preset model names (`claude-sonnet-5-5`, `gpt-4.1`, `gemini-2.5-flash`, etc.) and hardcoded `PRICING_TABLE`, only supports 1 key per provider entry, and lacks structured error classification, per-mode chains, or mid-stream state recovery.

## 2. Root Causes of the 4 Known Problems

| # | Problem | Root Cause Identified in v1 Code | v2 Fix Implemented |
|---|---------|----------------------------------|--------------------|
| 1 | **No Termux connection** | `AndroidManifest.xml` lacks `com.termux.permission.RUN_COMMAND`. No Termux package detection, no `RUN_COMMAND` intent launcher, no local HTTP/WebSocket Forge Engine server (`127.0.0.1`), and no shell command tool. | `TermuxBridgeClient` + embedded `ForgeEngineServer` script (Python HTTP + WebSocket server deployed to `~/forge/.engine/server.py` via `RUN_COMMAND` with local fallback mirror when testing on devices without Termux), bearer token auth (`chmod 600`), `/health` heartbeat, auto-reconnect, and 1-tap onboarding/repair. |
| 2 | **Agent gets stuck in a loop when asked to edit files** | `ProjectRepository.editFile` throws a generic `IllegalArgumentException("Target string was not found...")` without returning the nearest fuzzy match or line numbers. Furthermore, `AgentEngine` does not enforce read-before-edit (`readFilesInRun` tracking is missing), and `read_file` prepends `"%6d\t"` line numbers which models frequently copy into `old_str`. | Enforced **Read-Before-Edit** guard in executor, automatic stripping of accidental line-number prefixes in `old_text`, multi-tier whitespace/indentation-tolerant matching, nearest-region fuzzy match feedback with line numbers on failure, `insert_after_line` & `replace_line_range` support, and **Loop Guard** (rolling window of tool call signatures, 3x repeat block, 3x edit fail re-read + `ask_user` escalation, 8-step no-progress guard). |
| 3 | **Agent cannot install repos / tools** | No `run_command`, `install_package`, or `git_clone` tools exist in `AgentEngine`. No distinction between cloning a project vs installing a reusable tool/MCP server. | Full **Repo & Tool Installation Pipeline** (Section 11): intent disambiguation (`Clone as Project` in `~/forge/projects/` vs `Install as Tool` in `~/forge/tools/`), Termux/ARM compatibility analyzer (flags Docker, CUDA, x86, root), interactive **Plan Card** with approval, isolated `venv`/`npm` install, `--help` smoke test, MCP stdio & CLI tool registration, and **Tools Manager** in Settings. |
| 4 | **Fallback system is bad** | `ProviderRepository` hardcodes model names in `defaultPresets()`, couples 1 API key to 1 provider row, uses naive HTTP status checks, and has no separate Chat vs Build fallback chains or health/cooldown probing. | **Zero hardcoded models** (all models fetched live from `/v1/models`, `v1beta/models`, `/models` and cached in `ModelCacheEntity`), unlimited keys per provider (`ApiKeyEntity`), exact 9-class `ErrorClassifier` (`RATE_LIMIT`, `QUOTA_EXHAUSTED`, `AUTH`, `MODEL_UNAVAILABLE`, `CONTEXT_TOO_LONG`, `TRANSIENT`, `CONTENT_BLOCKED`, `NETWORK_DOWN`, `BAD_REQUEST`), `HealthStateEntity` tracking, separate Chat/Build chains, context auto-summarization on `CONTEXT_TOO_LONG`, and a built-in Fault-Injection Simulator for verifying Section 9.6 tests. |

## 3. Spec vs Existing Codebase Comparison & Upgrade Plan

- **Section 5 (Termux Bridge)**: Add `com.termux.permission.RUN_COMMAND` + `<queries>` for `com.termux` in `AndroidManifest.xml`. Create `data/termux/TermuxBridge.kt` managing Termux F-Droid vs Play Store detection, `RUN_COMMAND` bootstrap of `~/forge/.engine/forge_engine.py`, token auth, HTTP/WS execution, and `/health` heartbeat.
- **Section 6 (Agent Core & Prompts)**: Externalize editable prompts in `data/agent/AgentPrompts.kt`, add `AGENT.md` per-project memory auto-read/update, context window 70% summarizer, `LoopGuard`, read-before-edit + fuzzy diff `FileEditEngine`, `ask_user` interactive cards, and `plan`/`todo` live checklist.
- **Sections 7 & 8 (Providers & Server-Fetched Models)**: Remove all hardcoded model IDs from `ProviderRepository.kt` and `DomainModels.kt`. Add multi-key management, live connection testing with latency & plain-language diagnosis, and searchable bottom-sheet `ModelPicker` with `Tools`, `Vision`, `Long context`, and `Favorites` filters.
- **Section 9 (Fallback Engine)**: Implement `FallbackEngine.kt` with 9 error classifications, per-(key, model) health states, cooldown countdowns, strategy selection (Priority, Round-robin, Cheapest, Fastest), and Fallback Activity Log.
- **Sections 10, 11, 12 (Projects, Working Files, Tools, Attachments & RE Save Flow)**: Upgrade `ProjectRepository` to manage `~/forge/{projects,tools,checkpoints,outputs,.engine}`, add `WorkingFilesSheet` (Reading, Edited, Created, Deleted + per-file revert), APK/PDF/ZIP attachment analysis, and the `"Save this source to a project?"` `ask_user` workflow saving into `reference/<name>/` with `ANALYSIS.md`.
- **Sections 13, 14, 15, 16 (Soft Premium UI Redesign & Diagnostics)**: Upgrade `AppColors.kt` & `Theme.kt` with Dark (`#0E1014`), Light (`#F6F7F9`), AMOLED (`#000000`), and 5 user-selectable Accents (Indigo `#7C8CFF`, Teal, Violet, Amber, Rose), 3-item floating pill navigation (**Projects · Chat · Settings**), Onboarding wizard, Terminal drawer, and 15-section searchable Settings with Self-Test & Diagnostic Report exporter.
